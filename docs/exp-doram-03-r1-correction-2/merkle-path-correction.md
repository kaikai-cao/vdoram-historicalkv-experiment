## A0. 必须撤回的旧公式

`docs/exp-doram-03-r1-correction/mpc-witness-binding.md` §D1.1 写的是：

```
sib_t   = d_t·h_{t+1}^R + (1−d_t)·h_{t+1}^L      ← 错误
child_t = d_t·h_{t+1}^L + (1−d_t)·h_{t+1}^R
```

在 `d=1 表示走右` 的约定下，这个 `sib_t` 恰好等于 `child_t`：走右时它取右子、走左时它取左子。它不是兄弟，而是路径子节点本身。旧稿又写 `h_t − H(child_{t+1}, sib_t) = 0`，把无序的 `(child, sibling)` 直接送进哈希；既丢失了左右顺序，又使认证路径在 `d=1` 时退化为 `H(x,x)` 型关系。**该写法撤回**，以下为完整替代。

## A1. 固定位序（不得再写“实现时固定一种约定”）

| 对象 | 约定 |
| --- | --- |
| 叶子编号 | `ℓ ∈ [0,2^L−1]`，`ℓ = Σ_{k=0}^{L−1} 2^k b_k`，`b_0` 为最低位，`b_{L−1}` 为最高位 |
| 路径方向 | **根 → 叶**，`t = 0 … L−1`；`h_0` 为根，`h_L` 为叶子 bucket hash |
| 方向位 | `d_t := b_{L−1−t}`，即先取最高位；`ℓ = Σ_{t=0}^{L−1} 2^{L−1−t} d_t` |
| 左右语义 | `d_t = 0` → **左**；`d_t = 1` → **右** |
| sibling 数组 | `sib_{t+1}` 是深度 `t+1` 处**不在路径上**的那个子节点；数组按 `t = 0,1,…,L−1` 自根向叶排列 |
| 哈希输入 | 父节点恒为 `H(h^{left}, h^{right})`，**固定左在前、右在后**，绝不传 `(child, sibling)` |

`d_t` 是 `BIT(L)` 的输出位，本身是 bit，路径选择不额外产生 bit 约束。

## A2. 正确的左右选择公式

设深度 `t+1` 的两个子节点以**规范左右顺序**作为 witness 给出：`h^{L}_{t+1}`（左）、`h^{R}_{t+1}`（右）。则

```
child_{t+1}   = (1−d_t)·h^{L}_{t+1} + d_t·h^{R}_{t+1}
sibling_{t+1} = (1−d_t)·h^{R}_{t+1} + d_t·h^{L}_{t+1}
parent_t      = H(h^{L}_{t+1}, h^{R}_{t+1})          // 顺序固定，与 d_t 无关
h_t − parent_t = 0
```

- `d_t=0`（左）：`child=h^L`、`sibling=h^R`、`parent=H(h^L,h^R)`。
- `d_t=1`（右）：`child=h^R`、`sibling=h^L`、`parent=H(h^L,h^R)`。

两式各需 1 次 `FieldMul`，共 **2 µ/层**；`parent_t` 的哈希是 `H(2)=520 µ`。旧稿用 `H(child,sibling)` 时，右分支会把 `H(h^R,h^L)` 当成 `H(h^L,h^R)`，在 MiMC 链式哈希下两者不同， authenticit y 检查失败或给攻击者换来置换自由。

**单 sibling 变量的等价实现（本轮采用）**：为强制“旧、新路径只改一条”，令每层只提供**一个** `sib_{t+1}` 变量，由 `(child_{t+1}, sib_{t+1}, d_t)` 重建规范左右输入：

```
h^{L}_{t+1} = (1−d_t)·child_{t+1} + d_t·sib_{t+1}
h^{R}_{t+1} = (1−d_t)·sib_{t+1}   + d_t·child_{t+1}
```

仍是 2 µ/层；`sib_{t+1}` 在旧、新两条路径中为**同一变量**，因此 off-path 节点未被触碰是结构性的，而不是靠额外相等约束事后修补。这与任务给出的 `(child,sibling)` 公式等价（把 `h^L,h^R` 解为 `child,sibling` 的函数即可）。

### 附加线性约束

```
Σ_{t=0}^{L−1} 2^{L−1−t}·d_t − ℓ = 0        // 路径确实通向被访问的 bucket
```

该式是线性的，`λ=1, µ=0`。没有它，prover 可拿一条合法认证路径去证明另一个 leaf 的访问。

## A3. 旧根、新根与共享 sibling

对 `t = L−1 … 0`：

```
h_L^{old} − H(slots^{old}_{ℓ}) = 0
h_t^{old} − H(h^{L,old}_{t+1}, h^{R,old}_{t+1}) = 0
h_0^{old} − C_i^{Tree} = 0

h_L^{new} − H(slots^{new}_{ℓ}) = 0
h_t^{new} − H(h^{L,new}_{t+1}, h^{R,new}_{t+1}) = 0
h_0^{new} − C_{i+1}^{Tree} = 0
```

- 旧、新各算一次 `bucket hash` 与 `L` 次父 hash：认证成本 `H(4Z)+L·H(2)`，更新成本相同，必须分开计（沿用 correction 轮 A2.1/A2.2）。
- 旧、新路径的 `sib_{t+1}` 是同一 witness 变量（§A2 重建式）；只有 `child_{t+1}` 可不同。
- `slots^{new}_{ℓ}` 的 4Z 个字段必须逐项线性等于 eviction/writeback 输出；dummy 槽强制 `(0,0,0,0)`。

### A3.1 `L=3` 手工核对（玩具哈希 `H(x,y)=x+3y`，仅核对方向与顺序，不代表 MiMC 安全性）

记深度 1/2/3 的左右子为：深度 1 `(a,b)`、深度 2 `(c,e)`、深度 3 `(g,k)`，其中深度 3 的被选子节点就是 bucket hash。

**案例 1：`ℓ=2 = 010₂` → `d=(d₀,d₁,d₂)=(0,1,0)`，左→右→左**

| t | `d_t` | 规范 `(L,R)` | `child` | `sib` | 旧父 hash | 新父 hash |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 0 | `(a,b)` | `a` | `b` | `root=a+3b` | `root'=a'+3b` |
| 1 | 1 | `(c,e)` | `e` | `c` | `a=c+3e` | `a'=c+3e'` |
| 2 | 0 | `(g,k)` | `g` | `k` | `e=g+3k` | `e'=g'+3k` |

旧根 `a+3b = (c+3(g+3k))+3b`；把 bucket `g→g'` 后新根 `c+3(g'+3k)+3b`。同一 `k` 出现在旧、新两侧；若按旧稿 `sib₂=h^L=k?` 取反，则 `e` 会被算成 `g+3g`，与合法树不一致。

**案例 2：`ℓ=5 = 101₂` → `d=(1,0,1)`，右→左→右**

| t | `d_t` | 规范 `(L,R)` | `child` | `sib` | 旧父 hash | 新父 hash |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 1 | `(a,b)` | `b` | `a` | `root=a+3b` | `root'=a+3b'` |
| 1 | 0 | `(c,e)` | `c` | `e` | `b=c+3e` | `b'=c'+3e` |
| 2 | 1 | `(g,k)` | `k` | `g` | `c=g+3k` | `c'=g+3k'` |

注意两案例的**父 hash 输入顺序始终是 `(左,右)`**：案例 1 根为 `a+3b`，案例 2 根仍为 `a+3b`，而不是 `b+3a`。这正是必须恢复固定左右顺序的原因。

## A4. 递归 PositionMap 的变量一致性

取 `χ=4`，故 `off = a mod 4` 的位宽 `w=⌈log₂4⌉=2`；块号 `b_j = ⌊a/2^{2j}⌋`。

1. **位分解**：`a = Σ 2^k β_k`；`off_{j−1} = (β_{2j−2}, β_{2j−1})` 两 bit，`b_j` 取更高位（线性切片）。
2. **one-hot**：`τ_r = Eq₂(off, r)`，`r=0..χ−1`，`Σ_r τ_r = 1`（`λ`），`τ_r` 由 2-bit 相等构造，`χ·(2w−1)=3χ µ`。
3. **读取**：`ℓ_{j−1} = Σ_{r=0}^{χ−1} τ_r·block_j[r]`，`χ µ`。
4. **写回**：`block'_j[r] = block_j[r] + τ_r·(ℓ'_{j−1} − block_j[r])`，`χ µ`。
5. **新 leaf 范围**：`ℓ'_{j−1}` 的 `BIT(L_{j−1})`，`L_{j−1} µ`（已计入 correction 轮 REC）。
6. **同一变量约束**：`ℓ_{j−1}` 必须同时是 ③ 的读出值、下一层 `j−1` 的 Merkle 路径 leaf、以及该层 eviction 前缀比较的基准 leaf；用三条线性等式绑定同一 wire，不允许三个副本。
7. **下一层路径位**：`ℓ_{j−1}` 的 bit 分解 `BIT(L_{j−1})` 供下一层 `d_t` 与 eviction 前缀共用；这是 correction 轮未列的 `RECBIT` 项，本轮计入（见 `eviction-cost-correction.md` §B5）。

**结论**：A4 的**约束层**为 `CONSTRUCTED`（位宽、one-hot、读/写、跨层 leaf 同一性均已展开）；它不证明这些线值来自真实 MPC 执行（D2 仍 `BLOCKED`）。
