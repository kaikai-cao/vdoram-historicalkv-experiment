## A0. 撤回旧结论

**`r1cs-constraints.md` / `complexity-accounting.md` 的 `2,798,280` 乘法约束/步不再作为可信最终结果。** 它至少漏算：旧 bucket 内容哈希、新 bucket 内容哈希（只算了一次 bucket hash）、旧 stash commitment、eviction 的逐层秘密前缀比较与候选去重、递归层 leaf 读取/更新、随机多重集累加器、VM 结果承诺。以下为逐项重算。

## A1. 计数口径（必须先固定）

用成本向量 `Cost = (µ, β, κ, σ, λ)`：

| 符号 | 含义 |
| --- | --- |
| `µ` | 非线性乘法约束数（R1CS 中真正昂贵的乘法门）；**是所有其他计数中与总和可比的唯一数** |
| `β` | bit 约束数 `b(1−b)=0`，每个也贡献 1 个 `µ`，在向量中单列以便复核 |
| `κ` | 比较/相等操作次数（不是乘法约束数） |
| `σ` | 秘密选择的操作数/字段数（不是乘法约束数） |
| `λ` | 线性等式数（R1CS 线性组合，不计入 `µ`） |

### A1.1 原语成本（CONSTRUCTED）

| 原语 | 条件 | `µ` | 说明 |
| --- | --- | --- | --- |
| `BIT(ℓ)` | 域元素范围 `[0,2^ℓ)` | `ℓ` | `x=Σ2^i b_i` 为线性；`β=ℓ` |
| `EQ(ℓ)` | 两个输入已证明为 ℓ-bit | `2ℓ−1` | `eq=∏_{i=0}^{ℓ−1}(1−(a_i⊕b_i))`；`κ=1` |
| `CMP(ℓ)` | ℓ-bit 通用比较 | `≤6ℓ` | 给出上界，不当作精确值；本轮优化 eviction 后不使用通用比较 |
| `PREFIX(t)` | 两个 ℓ-bit 值前 t 位相等 | `t` | 每位相等 1 个 `µ` |
| `SEL(k,F)` | k 选 1、选 F 个域元素 | `kF` | 由 `SelectComposeGadget` 源码 VERIFIED：每个候选每个字段一次 `FieldMul` |
| one-hot 校验 | k 个选择位 | `k(k−1)/2` | 若选择位已由 EQ/位前缀直接构造且保证单热，可省 |
| `H(k)` | MiMC-Hash，k 个 preimage | `260k` | 固定 artifact 默认 65 rounds、`SBox=7`；`x⁷` 需 4 次乘法（VERIFIED 源码 + CONSTRUCTED 计数） |

**重要**：一次秘密比较绝不等于一次乘法；`EQ(20)=39 µ`，`CMP(20)≤120 µ`。旧稿把比较当作 1 个单位是错误的。

## A2. 逐项核算（任务 A1–A12）

记每层 `j` 的参数：`L_j`（树高）、`Z_j`、`R_j`、`χ`；`Q_j=R_j+Z_j(L_j+1)`（stash + 读入路径的合并槽数）；`E_j=2L_j+B+1`（多重集指纹编码位数，`B=128` 为 value 位宽）；`Q` 的选择均按单热选择器计数，且字段数逐项列明。

### A2.1 旧 Tree Merkle 路径认证

- 旧 bucket 内容哈希：`H(4Z)` → `1040Z` µ（这是**旧 bucket**，旧稿漏掉）。
- L 个父节点认证：`L·H(2)` → `1040L` µ。
- sibling 来自 witness；旧路径认证时验证 `h_parent=H(h_child,sibling)`，**sibling 本身不再重哈希其内部内容**。

小计：`µ_tree_auth = 1040(Z+L)`。

### A2.2 新 Tree Merkle 路径计算

- 新 bucket 内容哈希：另一个 `H(4Z)` → `1040Z` µ（旧稿只算一次 bucket hash，错误）。
- L 个父节点重算：`L·H(2)` → `1040L` µ。
- **同一 sibling 变量必须复用于旧、新两条路径**，否则无法保证“只改一条路径”；该相等是线性约束，不增加 `µ`。

小计：`µ_tree_update = 1040(Z+L)`。

### A2.3–A2.6 旧/新 Stash commitment

按 R1 原承诺实现（整个 stash 一次 `H(4R)`）：`2·H(4R)=2080R` µ。

**推荐修正（CONDITIONAL_CONSTRUCTION）**：把 stash 也做成 R 槽 Merkle（每槽 hash + `⌈log₂R⌉` 层父节点），旧路径认证 + 新路径更新共：

```
2·H(4) + 2·⌈log₂R⌉·H(2) = 2080 + 1040⌈log₂R⌉
```

R=179 时为 `10,400` µ/层，而非 `372,320` µ/层。下面给出两种报价，最终示例采用推荐修正版。

### A2.7 旧/新递归 PositionMap commitment

每层递归 pos-map 就是一个小型 Path ORAM，其 Tree 与 Stash 按 A2.1–A2.6 同样计费；顶层 `pos_d` 另外 `2·H(4χ)=2080χ` µ（一次）。**不能只承诺主树**。

### A2.8 每层秘密 leaf 读取与更新

- 地址位分解一次（`BIT(L₀)`），高位切片给 `b_j`，低位给 `off_{j−1}`；递归层不再重复位分解。
- 每层从 χ 个 leaf label 中选一个：`SEL(χ,1)` → `χ` µ；选择器由 `off_{j−1}` 的 2-bit EQ 构造：`χ·EQ(2)=3χ` µ。
- 写回同槽再 `SEL(χ,1)` → `χ` µ。
- 新 leaf 范围约束 `BIT(L_{j−1})` → `L_{j−1}` µ。

小计（j≥1）：`µ_rec,j = 5χ + L_{j−1}`；主层新 leaf 为 `L₀`。

### A2.9 Eviction：秘密比较、候选选择、内容选择

优化点：bucket 在路径第 t 层覆盖的 leaf 集合 = 访问 leaf 的前 t 位相同的 block，因此用位前缀相等而非通用数值比较。

1. 对每个 stash 槽、每个深度 t 计算前 t 位相等：`PREFIX(t)=t` µ；总 `R·L(L+1)/2` µ。选择器数量 = `R·L(L+1)/2`，每个选择 1 bit。
2. 每个深度、每个 bucket slot（Z 个）从 R 个候选中选 4 个字段 `(addr,val,leaf,valid)`：`4·SEL(R,4)=4R` µ；再加 eligibility gating `R` µ → `5R` µ/槽。总 `5ZRL` µ。选择器数量 = `Z·L·R`，被选字段数 = `4ZLR`。
3. 同一深度内避免重复选同一 stash 槽：对已选槽做 exclusion gating，保守计 `Z(Z−1)RL/2` µ。

小计：

```
µ_evict,j = R L(L+1)/2 + 5ZRL + Z(Z−1)RL/2
```

旧稿的 `2ZL+R+R²` 既漏了前缀比较，也漏了 4 字段选择，撤回。

### A2.10 Stash 查找、插入、删除、去重

在合并集合 `Q=R+Z(L+1)` 上统一处理：

- `Q` 次 `EQ(L)`：`Q(2L−1)` µ，`κ=Q`。
- `valid ∧ eq`：`Q` µ。
- result 选择：`SEL(Q,1)` → `Q` µ（`σ=1`）。
- Store 条件写 val 与 leaf：`2Q` µ（`σ=2`）。
- insert/delete 通过固定槽位与 eviction 的 gating 实现，不做数组搬移；无额外 `µ`。

小计：`µ_stash,j = Q(2L+2)`。

去重/多重集采用 `stash-soundness.md` 的 B1（commit-then-challenge 随机指纹），Fingerprint 成本见 A2.11；若改用 B3 确定性匹配矩阵，成本为 `Q(Q−1)+4Q²` µ/层（字段条件等式口径），或按整字段 ℓ-bit 相等为 `Q(Q−1)/2·(2L−1)` µ/层，示例中均显著更贵。

### A2.11 多重集随机指纹（B1）

对 `enc = addr + 2^L·val + 2^{L+B}·leaf + 2^{2L+B}·valid`（`<p`，无碰撞编码），取两个独立挑战 `ρ₁,ρ₂`，比较旧/新合并集合的 `Σρ^enc`：

```
µ_acc,j = 4·Q_j·E_j      // 两个挑战 × 旧/新两侧 × Q 个编码 × E 位平方乘
```

`β,κ` 另计；挑战由 witness commitment 后派生，生成成本在电路外。soundness 误差见 `stash-soundness.md`。

### A2.12 历史日志 append 与 VM 绑定（全局一次）

- `C^{Hist}=H(C_i^{Hist}, step, trace_addr, is_mem_op, is_mem_write, result)`：`H(6)=1560` µ（旧稿 `H(5)=1300` 少算一项；若把 step 与 C 合并为一项则是 5 preimage，本文按 6 计保守）。
- `in_mem_val=result`：线性等式，`µ=0, λ=1`。
- 若 result 不公开：`C^{result}=H(2)=520` µ。
- step/version 递增：线性，`µ=0`。

全局小计：`µ_vm_hist = 2080`。

## A4. 成本分类回答（逐项）

| 要求 | 回答 |
| --- | --- |
| 每个哈希一次还是两次 | 旧/新 bucket 各一次；旧/新 stash 各一次；旧/新 Merkle 父路径各 L 次；顶层 root 两次 |
| 旧 sibling 是否重哈希 | **不重哈希内容**；作为 witness hash 直接复用，旧/新路径共用同一变量 |
| 认证 vs 更新 | 认证：`H(4Z)+L·H(2)`；更新：另一个 `H(4Z)+L·H(2)`；必须分开计 |
| 选择器数量 | eviction：每深度 `R` 个候选、Z 个槽、4 字段；stash：`Q` 个候选、1–2 字段；递归：χ 个候选、1 字段 |
| 比较≠乘法 | `EQ(20)=39 µ`、`CMP(20)≤120 µ`；eviction 用 `PREFIX(t)=t`，不再把比较当 1 |
| 未能精确计算者 | 通用 `CMP(ℓ)` 只给 `≤6ℓ` 上界；实际后端线性约束/gadget 展开未固定，标 UNKNOWN |
