# EXP-DORAM-08-R1-C1：最终决策

## 最终决策：`CONDITIONAL_PASS`

> 四个候选：`PASS_TO_MPC_MICROBENCHMARK` / `CONDITIONAL_PASS` / `NO_GO_COST_ADVANTAGE` / `BLOCKED_MODEL_INCONSISTENCY`。
> 选择 `CONDITIONAL_PASS`：两项模型不一致已修复并通过代码+符号双重验证，E1 的优势区间真实存在但收窄且仍依赖未证实条件；**不**因符号模型自洽就升级为 `PASS_TO_MPC_MICROBENCHMARK`。

---

## 1. 修正后 E1-A 是否仍有只读优势区间？

**有，但边界已修正为严格的 `n < T/2`。**

`C_E1A(T,n) = (T−1)(393n−2)`，`C_E0(T) = 393T(T−1)/2 − 2(T−1)`。两者的 `−2(T−1)` 完全抵消，得到 `n < T/2`；`n = T/2` 恰好相等（TIE），`n > T/2` 则 E0 更便宜。

R1 代码实现曾因把 `fetch_a(1)=391` 当线性系数而把阈值算成偏大的 `32.1586/128.6496/514.6138/2058.4706`（T=64/256/1024/4096）；C1 修正为精确的 `32/128/512/2048`。**优势区间本身在 R1 文档符号推导中已正确，错误仅在代码与 CSV 列**；不存在"优势消失"。

## 2. 修正后 E1-B 是否仍有只读优势区间？

**有，区间为 `n < (393T−4)/780 ≈ 0.5038T`，略宽于 E1-A。**

E1-B 因无 LowBit 常数项，E0 的 `−2(T−1)` 不被抵消，阈值含微小正截距 `4/780 ≈ 0.0051`。数值例（`T=64`）：`n=32` 时 E1-B 比值 `0.9925`（胜），而 E1-A 恰为 `1.0000`（TIE）；`n=33` 时两者皆败。E1-B 的阈值列本就正确，本轮保持不变。

## 3. 读写混合场景是否依赖 STORE 位置？

**明确依赖，不能套用只读阈值。**

- step 0 STORE 无本步 Fetch，强制 `c_upd_separate=391`；step>0 STORE 仅在显式允许共享 eq 时用 `c_upd_shared=2`。
- 统一条件：`n < [A0 − cx(T−1)] / [fx(T−1)+U]`，其中 `U = w0·391 + wpos·(2 或 391)`，`(fx,cx)` 为 `(393,−2)`（A）或 `(390,0)`（B）。
- 数值例（`T=128`）：只读阈值 `64.000`；仅 step 0 STORE 降至 `63.503`；127 个 step>0 shared STORE 降至 `63.676`——单个 step 0 STORE 的冲击大于 127 个 shared STORE 的合计冲击。
- 全 `separate` 时阈值约减半：E1-A `63.183 → 31.956`，E1-B `63.658 → 32.076`（100% STORE）。

因此"能否复用本步比较结果"与"STORE 落在哪一步"都是成本模型的必要变量；成本函数必须接收具体 STORE step 集合，而非仅接收 W 数量。

## 4. R1 敏感性结论哪些保留、哪些撤回？

**保留：**

- R1 源码推导参数与三项勘误：`c_eq=389`、`c_sel=1`、`c_upd_shared=2`、`c_upd_separate=391`；`fetch_A=393n−2`、`fetch_B=390n`；step 0 STORE 强制 separate。
- 源码权重 `(389,2)` 下的胜负分布：E1-A/E1-B 各 `99/160` 胜；`symbolic_costs` 中 10/16 个 `T/n≥4` cell 胜、`T/n≤1` 全败。
- 压力权重 `c_eq/c_sel=1, c_upd/c_sel=100` 下 90% STORE 仅 3/16 胜、中位反劣约 9.3×——优势依赖 `c_eq ≫ c_upd` 的结论保留。
- `E1-A − E1-B = (T−1)(3n−2)`、追加成本三模型同项、线性/barrier/三元组模型。
- R1 总体 `CONDITIONAL_PASS` 的实质理由（有界域、权重依赖、eq 复用未证、后端缺 SPDZ MAC/auth）。

**撤回：**

- `sensitivity_raw.csv` 中 E1-A 的四个 `threshold_n_continuous` 数字（32.1586 / 128.6496 / 514.6138 / 2058.4706）→ 改为 32 / 128 / 512 / 2048。
- `e1a_total_closed` / `e1b_total_closed` 的 `(T−1)·append_mults` 写法 → `T·append_mults`（执行器 L116+L405 证明每步追加）。
- `test_three_models_common_append` 中 `(T−1)*7` 的错误断言 → `T*7`。
- 任何"E1-A 阈值略大于 T/2"的表述（若有）→ 改为恰好 `T/2`。

**不受影响**：R1 五份历史文档原文、EXP-DORAM-08 原始 CSV、EXP-DORAM-07/07-R1 CSV、上游 VDORAM、C#/Rust 执行路径，全部零修改。

## 5. 是否可以进入最小 MPC 微基准？

**本轮不建议立即进入；可在满足前置条件后进行最小原语权重微基准，本轮不自动启动。**

理由：

1. 模型现已自洽（逐步=闭式=交叉条件=CSV 四者一致），但自洽不等于有真实成本优势——`c_eq=389` 这一主导假设尚未由执行侧实测验证。
2. E1 的优势依赖三个未证实前提：目标系统地址域严格有界（E1-B）、`eq` 可跨读写复用（`shared`）、比较远贵于更新（`c_eq≫c_upd`）。
3. 当前 VDORAM C#→Rust witness 路径缺少 SPDZ MAC/auth 契约（EXP-DORAM-06 结论不变），后端**不能直接承载**该方案。

若进入，范围限定为：在严格有界域下，最小化原语权重验证（`c_eq` 的 386 次秘密逆元乘法、`c_upd_shared=2`、SelectCompose 每行一次 FieldMul），以 E1-A 为对照、E1-B 为主构造；不做完整 E1 电路、不做端到端 SPDZ、不接入生产 witness 接口。

## 7. 下一阶段允许 / 明确不做

**允许**：① 在严格有界域前提下做最小 MPC 原语权重微基准（仅验证上述三个计数假设）；② 补充目标系统地址域的实证材料；③ 若取得电路级证据，再评估 eq 复用。

**明确不做**：不自动启动 MPC 微基准或任何 EXP-DORAM-09；不实现真实 SPDZ、不接入 witness 接口；不修改上游 VDORAM；不把参数扫描称为 MPC 实测；不把乘法数写成 R1CS 约束数或网络字节数；不再为维持 E1 胜出比例而调整权重或参数。

**本轮结束后停止。** 成本模型勘误到此收敛：后续只依据修正后的模型判断最小微基准是否值得做，不再延伸公式勘误。
